# 日本語特化小規模LLM「Qwen3.5-0.8B-Japanese-SFT-v2」はLogit Routerとして使えるか？2,500問の大規模ベンチマークで徹底検証してみた

近年、LLMアプリケーションにおいて「ユーザーのクエリを適切な専門モデルやツール、プロンプトへ即座に振り分ける」**ルーター（LLM Router）** の重要性が高まっています。

一般的なアプローチでは、分類用のプロンプトを与えてモデルにテキストを生成させる（Autoregressive Generation）か、小型の分類器を別途ファインチューニングすることが多いですが、これらには「レイテンシが大きい（数百ms〜数秒）」「メンテナンスコストが高い」という課題があります。

そこで注目されているのが **Logit Router（ロジットルーター）** です。
Logit Router は、プロンプトの次の1トークン予測における候補ラベル（A, B, C...）の **ロジット（未正規化対数確率）を1回のForward Passで直接抽出・比較** して判定します。テキスト生成ループを回さないため、**数十ミリ秒** という圧倒的な低レイテンシで判定が完了します。

今回は、日本語SFTモデルとして公開されている **[Takenoko12345678/Qwen3.5-0.8B-Japanese-SFT-v2](https://huggingface.co/Takenoko12345678/Qwen3.5-0.8B-Japanese-SFT-v2)** およびその **[GGUF量子化版（Q4_K_M / Q8_0）](https://huggingface.co/Takenoko12345678/Qwen3.5-0.8B-Japanese-SFT-v2-GGUF)** を取り上げ、「日本語環境でのLogit Routerとして実用可能か？」を **2,500問の実践的テストケース** を用いて徹底検証しました。

---

## 結論サマリー

- **利用可否: 極めて実用的**
  0.8Bという超軽量サイズでありながら、ベースライン（Qwen2.5-1.5B-Instruct）を超える **正解率 89.2% / Macro-F1 0.88** を達成。
- **圧倒的な低レイテンシ**
  1.5Bモデルが約75msかかる処理を、**40〜55ms** で判定完了。
- **GGUF量子化（Q4_K_M）の有用性**
  4-bit量子化を施しても精度低下はわずか **1.1%**（89.2% → 88.1%）。最小限のVRAM環境やエッジ・ローカル端末での運用にベストバランス。
- **日本語ノイズへの頑健性**
  方言・口語・誤字・長文・否定表現などが混在する過酷な条件下でも高い精度を維持。

## 測定環境と実行速度に関する注意事項

> [!NOTE]
> **実行速度（レイテンシ）はハードウェア環境や実行バックエンドに大きく依存します。**
> 掲載している数値は同一測定環境における**相対比較（A/Bテスト）の目安**としてご参照ください。

### 今回の測定ハードウェア環境
- **GPU**: NVIDIA GeForce RTX 3060 12GB (VRAM帯域: 360 GB/s)
- **CPU / Host**: Linux x86_64, PyTorch 2.x + CUDA 12.x / llama.cpp (GGUF実行)
- **バッチサイズ**: 1（リアルタイムAPIリクエストを想定した逐次推論）

### 実行環境による速度変動のポイント
1. **GPUアーキテクチャ・メモリ帯域**:
   - データセンター向けGPU（A100 / H100 / L4 など）では、メモリ帯域幅が大幅に広いため、本検証の数値（40〜55ms）からさらに短縮され、**10〜20ms台** への到達が期待できます。
   - 逆にVRAM容量が逼迫していたり、PCIeバス経由での転送オーバーヘッドがある環境ではレイテンシが増加します。
2. **CPU / オンデバイス環境（llama.cpp / GGUF）**:
   - GGUF（Q4_K_M）をCPU単体（Apple Silicon Mac や x86 CPU）で実行する場合、メモリ帯域およびスレッド数に依存しますが、概ね **80〜150ms** 程度での動作が一般的な目安となります。
3. **並列度と同時リクエスト数**:
   - 本ベンチマークは「単一リクエストが到着した際のターンアラウンドタイム（p50/p95）」を測定しています。同時リクエスト数（Concurrent requests）が多い場合は、vLLMやTGIなどのバッチングエンジンとの組み合わせ、または複数インスタンスでの分散が推奨されます。

## ベンチマーク結果

### 1. 精度とレイテンシの比較

| モデル | 形式 / 量子化 | 正解率 (Accuracy) | Macro-F1 | 誤字ノイズ耐性 | 長文耐性 | p50 レイテンシ | p95 レイテンシ |
| :--- | :---: | :---: | :---: | :---: | :---: | :---: | :---: |
| **Qwen3.5-0.8B-JP-SFT-v2** | **HF (bfloat16)** | **89.2%** | **0.88** | **85.0%** | **88.0%** | **55.2 ms** | **60.1 ms** |
| **Qwen3.5-0.8B-JP-SFT-v2** | **GGUF (Q8_0)** | **89.0%** | **0.87** | **84.8%** | **87.9%** | **48.0 ms** | **52.1 ms** |
| **Qwen3.5-0.8B-JP-SFT-v2** | **GGUF (Q4_K_M)** | **88.1%** | **0.86** | **84.1%** | **87.2%** | **40.5 ms** | **45.2 ms** |
| Qwen2.5-1.5B-Instruct | HF (bfloat16) | 87.5% | 0.85 | 81.0% | 84.5% | 75.3 ms | 80.4 ms |

### 2. 結果の考察

#### ① パラメータ数は半分以下、精度はベースライン超え
ベースラインとして比較した `Qwen2.5-1.5B-Instruct`（1.5Bパラメータ）に対し、`Qwen3.5-0.8B-Japanese-SFT-v2`（0.8Bパラメータ）はモデルサイズが約半分にもかかわらず、日本語ルーティング精度で **+1.7%**、Macro-F1で **+0.03** 上回る結果となりました。
日本語SFTによって「〜というわけではない」「どないしたらええの？」といった文脈表現を正確に捉えられることが要因と考えられます。

#### ② レイテンシは最大 46% 短縮
推論処理において生成を行わないLogit抽出の強みと、0.8Bの軽量性が相まって、GGUF Q4_K_M では **p50: 40.5ms / p95: 45.2ms** を記録しました。1.5Bベースライン（75.3ms）と比較して大幅に高速化されており、リアルタイム性が要求されるGateway層に最適です。

#### ③ GGUF（Q4_K_M）が驚異的なコストパフォーマンス
GGUFの4-bit量子化版（Q4_K_M）は、メモリ消費を1GB未満に抑えながら、未量子化版と比較してわずか 1.1% の精度差に収まっています。低リソースなサーバやローカル環境での配備には、Q4_K_M がもっとも推奨される構成です。

## 実装・運用のポイント

### トークナイザ仕様への対応
LLaMA系などのトークナイザでは選択肢文字の直前にスペース（`" A"`）が必要な場合がありますが、Qwen系トークナイザではダイレクトに `"A"`, `"B"`, `"C"` を指定することで正しいToken IDが割り当てられます。
実装側で `is_qwen` に応じたトークンID抽出を行うことが重要です。

### コード例（Python）

```python
from logit_router.router import LogitRouter

# GGUF版（Q4_K_M）を使用する場合
router = LogitRouter(
    model_id="Takenoko12345678/Qwen3.5-0.8B-Japanese-SFT-v2-GGUF",
    gguf_file="qwen3.5-0.8b-japanese-sft-v2-q4_k_m.gguf",
    device="cuda",  # CPU実行も可能
)

# ルーティング実行
result = router.route(
    context="ユーザーからの問い合わせログ",
    instruction="来月のサブスクリプションを解約したいのですが、違約金は発生しますか？",
    choices=[
        "解約・退会手続き",
        "料金・請求の確認",
        "技術サポート・不具合",
        "機能へのご要望"
    ]
)

print(f"最適なルート: {result['best_choice']}")
print(f"信頼度スコア: {result['confidence']:.2f}")
# => 最適なルート: 解約・退会手続き
```
